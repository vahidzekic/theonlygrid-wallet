How TOG Wallet works

In short: the key is made on your device, the app builds and signs each transaction, and the server only relays it to the network.

Where the key comes from

When you create a TOG account, your device makes a random account root key. From it, by the same rule the TOG Console uses, the app derives your Hub signing key (Ed25519), and from that your address. So the address is the same on every device.

The TOG account service keeps the root key only locked: by your password, by the 24 words and by your devices' keys. It cannot unlock it. On the device the keys live in the system keystore (Keychain, Credential Manager, Android Keystore, Secret Service).

What happens when you send

  1. The app asks the network for your balance and your next transaction number.
  2. It builds the transaction itself: network, you, recipient, amount, number. It never signs anything the server sends it.
  3. After you confirm, it signs with the key on your device and sends it to the server, which passes it to the Hub.
  4. Once the transaction is in a block, the app shows it as done.

The server could show a wrong balance, but it cannot make or change a transaction you did not confirm. Checking balances with proofs from the network (light client) comes in a later version.

What the server sees

The public RPC gateway (rpc.theonlygrid.com) sees your IP address, the address you read and the transactions you send. All of that is public on the network anyway, except the link between your IP and your address, which the gateway keeps only briefly in its logs. See the privacy policy.

Network and addresses

An address is 20 bytes, shown as 0x and 40 hex digits, the same on the Hub and on every TOG chain. Every transaction carries a network tag, so a testnet transaction is not valid on mainnet. The app checks the tag before every send and clearly shows TESTNET.

The technical description is the spec TOG-SPEC-0023.

TOG Wallet is a test version on The Only Grid testnet. Test-TOG has no monetary value.
